## Project context

- Organization profile, shared CI and tooling: the org-wide defaults (community health files, issue and PR templates), the reusable workflows and actions, and the org standards in `docs/standards/`.
- Kind: `npm` · team: `krizaka` · registry entry: [repos.json](https://github.com/krizaka/.github/blob/main/repos.json) (generated by `scripts/gen-repos.mjs`, never hand-edited).
- This repository holds the AGENTS.md template itself (`docs/standards/agents-template.md`, `scripts/agents-md.mjs`) and the engineering charter (`AGENTS.template.md`): change those only in their own PR.
- Read this file first, then the [engineering charter](https://github.com/krizaka/.github/blob/main/AGENTS.template.md) for what you touch.
- `CLAUDE.md` is the one line `@AGENTS.md` (or a symlink to this file): never a second copy of it.

## Essential commands

```bash
npm test          # node --test over tests/, scripts/*.test.mjs and the action tests, with coverage
npm run precheck  # the dispatch-contract test, the fast check before a push
```

- The package has no dependency: `package.json` only gives the shared `node-ci` workflow a test script. `actions/security-tools` is not in `npm test`: it needs gitleaks and zizmor, run by `lint-workflows.yml`.
- Run them on what you changed before every push; CI runs the rest.

## Architecture & conventions

- Follow the [krizaka-engineering skill](https://github.com/krizaka/krizaka-skills/blob/main/skills/krizaka-engineering/SKILL.md); search its [packages reference](https://github.com/krizaka/krizaka-skills/blob/main/skills/krizaka-engineering/references/packages.md) before writing anything generic.
- Layout: `.github/workflows/` (reusable and org workflows), `actions/` (composite actions), `scripts/` (dependency-free `.mjs` tools with their `*.test.mjs`), `docs/standards/` (the org standards), `profile/` (the org page), `workflow-templates/`, `deploy/`, `orchestration/`.
- Keep scripts dependency-free Node (`node:` imports only); a script exports its pure functions and runs `main` only when it is the entry point, so a test imports it.
- Take libraries first: a missing generic function goes into its `@krizaka/*` package first, never a local copy.
- Keep ports and adapters: pure logic in functions, the clock, the filesystem and `gh` passed in.
- Write one job per function: cognitive complexity ≤ 15, nesting ≤ 2, a body under 60 lines; the same block twice is a function.
- Name things by what they do; no `*Utils`, `*Helper`, `*Manager`. Files in kebab-case.
- A workflow follows the [krizaka-github-actions skill](https://github.com/krizaka/krizaka-skills): every `uses:` pinned by full commit SHA with the release in a comment, least-privilege `permissions:` per job, `timeout-minutes` on every job (`scripts/check-timeouts.mjs`), every required check reporting on `merge_group`.
- A change to a reusable workflow reaches every repository: keep its inputs and outputs backward compatible, and run `npm run precheck` (dispatch contract).
- Hierarchy: this root file holds the rules of the whole repository; a sub-folder with its own rules adds a local `AGENTS.md` that says only what differs there. The nearest file wins.

## Guard-rails & known pitfalls (read before coding)

- A recurring mistake becomes one rule here, one line; its detail goes to `docs/` and is linked from References.
- The checks are the judge ([ADR-015](https://github.com/krizaka/krizaka-internal/blob/main/docs/adr/.github/ADR-015-ai-code-audit-measured-and-enforced.md), [guards](https://github.com/krizaka/.github/blob/main/docs/standards/guards.md)): never `--no-verify`, never a new `eslint-disable`, never a raised ratchet or baseline; a rule is never silenced to get green.
- Anti-slop, what a model tends to write and the code does not need:
  - No defensive null on `@NullMarked` code: no `Objects.requireNonNull` or `if (x == null)` on a value the type guarantees (NullAway); a new package is `@NullMarked` (ArchUnit).
  - A closed set is a type (enum, sealed interface, `as const` object), never a string compared by hand; strategies are a `Map<Kind, Strategy>` built once (PMD / ArchUnit, ast-grep `no-enum-string-compare`).
  - HTTP in Java is a DTO record, `@Valid` and `ProblemDetail`: no `Map.of("error", …)`, no entity in a response, one `@RestControllerAdvice` per service (ArchUnit).
  - Use `?.` and `??` in TypeScript, not a chain of `&&` or a ternary on null (the ESLint rules `prefer-optional-chain` and `prefer-nullish-coalescing` are not in `@krizaka/config` yet).
- Commit identities are an allow-list (`scripts/commit-identities.json`): never write a made-up e-mail or `Co-authored-by` line; `scripts/check-trailers.mjs` refuses it.
- The registries (`repos.json`, `docs-map.json`, `policy.json`) and the profile README are generated: change the generator or its source, then regenerate; never hand-edit the output.
- A bug means a missing guard: start a fix with a failing test; the journey (end to end) proves the feature.
- Never invent a URL, a law article, a price or a figure you did not read; write `TO VALIDATE` and say who decides.
- Never commit a secret, a capture or a log; no production data in a session, only the dev data.
- No Krizaka e-mail address on a public page ([`no-public-email`](https://github.com/krizaka/.github/blob/main/docs/standards/no-public-email.md)). This repository is public: write nothing private in it.
- Keep the edit hook in `.claude/settings.json`: `npx --yes -p @krizaka/config krizaka-edit-check` on `Edit|Write` (this repository does not depend on `@krizaka/config`).

## Expected validation workflow

- [ ] Compile, format, lint and test what changed (the commands above); fix the cause of a red, never the guard.
- [ ] The « before you push » checklist of the skill holds for what changed.
- [ ] A feature or fix PR names its journey (`Journey: <name>` or `Journey: n/a — <reason>`).
- [ ] A change to AGENTS.md passes the `agents-template` check (`problemsOf` in `scripts/agents-md.mjs`).
- [ ] README and generated docs still say what the code does; the [docs map](https://github.com/krizaka/.github/blob/main/docs-map.json) category of the change is updated.
- [ ] One issue, one small PR (`Closes #<n>`); merge only with green CI.
