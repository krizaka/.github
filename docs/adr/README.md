# Organisation ADRs

Decisions that span several Krizaka repositories. A decision that belongs to one repository lives in that repository
(`krizaka-ui/docs/adr`, `sovkora/docs/adr`…).

| ADR | Decision | Status |
|---|---|---|
| [ADR-001](ADR-001-krizaka-accounts.md) | The sign-in standard of every Krizaka product (krizaka-users, `SignInProviders`, linking by verified e-mail, native PKCE) and Krizaka accounts for the krizaka.com properties (a thin `krizaka-accounts` host with comments) | Accepted (runtime waits on cost approval) |
| [ADR-002](ADR-002-dev-preview-status-is-data.md) | « Dev preview » is a checkable bar (docs/standards/dev-preview.md); a product's status is data (`dev-preview.json`), gated at krizaka.com's build | Accepted |
| [ADR-003](ADR-003-mobile-service-discovery.md) | Mobile apps discover their backend addresses from a signed manifest on krizaka.com (`@krizaka/discovery`, Ed25519, host allow-list), so a URL change never forces a store republish | Accepted |
| [ADR-004](ADR-004-expo-app-shell.md) | Expo apps share one package, `@krizaka/app-client` (session, discovery, API client, gates, auth, settings) and a wiring-only `template-expo-app` |  Accepted |
| [ADR-005](ADR-005-tauri-app-kit.md) | Tauri apps share one Rust crate, `krizaka-tauri-kit` (folder scope, files, menu bar, deep links, update), its TypeScript bindings and a wiring-only `template-tauri-app` | Accepted |
| [ADR-006](ADR-006-krizaka-ts-organize.md) | Krizaka TS (`krizaka/krizaka-ts`, backend packages under `@krizaka/`) and `@krizaka/organize`: name, avatar, description, tags, collections and an undeletable default collection for every entity, a table-per-kind generator with the invariants in the database | Accepted |
| [ADR-008](ADR-008-native-video-bunny-stream.md) | Native video behind `@krizaka/ui/native`: playback stays on `expo-video` with server-signed Bunny addresses or tokens, uploads signed by the server (no key in the app), Bunny's React Native SDK adopted only after a trial on our Expo SDK and the New Architecture | Proposed (design; trial waits, a former product paused) |
| [ADR-009](ADR-009-prices-are-data.md) | Prices are data: one price catalogue per product in `@krizaka/settings`, edited by the admin, versioned with effective dates, audited; public pages read only the catalogue | Accepted (shipped; Sovkora Java side planned) |
| [ADR-010](ADR-010-krizaka-storage.md) | `krizaka-storage` (`@krizaka/storage` and the Spring block): the admin chooses where files live (S3-compatible or HTTP), the user may choose when allowed, residency claims are generated from the configuration | Accepted (design) |
| [ADR-011](ADR-011-default-media-in-the-org-json.md) | Default media are central: Bunny `defaults/v1/<kind>/`, listed in the `defaults` section of the Krizaka org JSON (`@krizaka/org`), read with `listDefaults` / `defaultFor`, never hard-coded or bundled | Accepted |
| [ADR-012](ADR-012-licensing-libraries-open-products-fair-source.md) | Libraries stay Apache-2.0 (DCO); products (Verikora, Folioviv, the Sovkora engine) move to FSL-1.1-ALv2 from the licence commit, Apache-2.0 after two years (CLA); content assets go private by Oussama's decision; trademarks never licensed; a licence gate on the SBOM | Accepted (libraries) · Proposed (products, `needs-oussama` PRs) |
| [ADR-013](ADR-013-guards-and-local-sonar.md) | Sonar rules run locally (sonarjs in `@krizaka/config`; PMD + SpotBugs in `krizaka-parent`; ArchUnit for the architectural lessons); shift-left to the IDE and hooks; one source per rule set; less in-house (ESLint suppressions, Renovate, add-to-project) | Accepted |
| [ADR-014](ADR-014-bunny-org-cdn-and-apps.md) | The Bunny media library, layout v2: `org/v<n>/` (Krizaka's own data and defaults: org JSON, apps config, defaults and avatar tones, brand, maps, films, discovery), then `sites/<site>/<kind>/` (www, blog, ui, java, each dev site), then `apps/<app>/` (runtime data only), and `pr-assets/`; at most five folders; a new write outside v2 fails; unused old objects are deleted | Accepted (migration in progress) |
| [ADR-015](ADR-015-ai-code-audit-measured-and-enforced.md) | The external « AI code » audit, measured (`tools/code-health`) then enforced as build rules: NullAway + JSpecify `@NullMarked` (Error Prone only as its host), closed sets as types, DTO + `@Valid` + `ProblemDetail`, PMD limits and ArchUnit rules in `krizaka-parent` / `krizaka-quality` / `krizaka-test-support`, the type-aware strict layer of `@krizaka/config`, an anti-slop template section and a single-file Claude hook; existing debt ratcheted, no flag day | Accepted |
| [ADR-016](ADR-016-identity-federation-trusted-devices-risk.md) | Identity: federation by standards (OIDC, SAML 2.0, SCIM 2.0; Okta is one IdP), krizaka-users kept over Keycloak/Zitadel/Ory, passkeys first, NIST 800-63B-4 passwords, trusted devices (device keys, refresh rotation, DPoP), an explainable risk engine under Loi 25, ports in the open core and enterprise adapters (SAML/SCIM) in a private repository, identity secrets sealed under `AUTH_VAULT_KEY` | Accepted (design; paid items need Oussama) |
| [ADR-017](ADR-017-e2e-journeys-test-shape.md) | Tests prove the product: journeys first, a product never tests the library; catalogue format, budgets, flake policy |
| [ADR-018](ADR-018-workflows-by-concern-profiles-budgets.md) | Workflows by concern (`<area>-<what>.yml`, literal job names, renames never rename a check), repository profiles with default sets (`docs/standards/ci-profiles.json`), speed budgets PR < 10 min / queue < 15 min measured weekly (`org-ci-speed.yml`), buildpacks where they fit, a daily repository health scorecard composed from the existing checks | Accepted (slice 1 shipped) |
| [ADR-019](ADR-019-java-building-blocks-on-github-packages.md) | The Java building blocks are published on GitHub Packages (no Maven Central Publisher Pro): release with `GITHUB_TOKEN`, consumers read through `krizaka-parent`, versions 0.1.0/0.2.0 stay on Central | Accepted (roll-out krizaka-internal#1879) |
| [ADR-020](ADR-020-krizaka-managed-document-storage.md) | Krizaka managed document storage as an option the admin turns on (bring-your-own stays the default): OVHcloud Beauharnois (QC) with a Toronto replica (AWS Canada as the fallback), per-tenant envelope encryption under a KMS port, expiring audited sharing, Private (end-to-end) folders, Mac/phone encrypted cache and sync, consent grants for Sovkora packs, measured RPO/RTO and availability published from drills and probes | Proposed |
| [ADR-021](ADR-021-java-building-blocks-one-repository-one-version.md) | The Java building blocks (platform-kit, users, notifications, billing) become Maven modules of krizaka-build with one version and one release; the BOM manages them at `${project.version}`, the reactor orders builds | Accepted (roll-out krizaka-internal#1878) |
| [ADR-022](ADR-022-dev-and-prod-environments.md) | Code-name hosts are dev (`noindex`), commercial hosts are prod (indexed), no redirect between them; the same image digest promoted by tag; prod empty of dev data; one prod DigitalOcean team shared by the products (one app each, one Postgres cluster with a database and roles per product); rolled out one product at a time, Verikora first | Accepted |
| [ADR-023](ADR-023-one-iac-stack-prod-nonprod-separation.md) | One OpenTofu root stack for every environment (`dev` / `prod`) and provider (`digitalocean`, another cloud, `machine` = one server with Docker Compose, tested on a CI runner), same outputs per role; prod and non-prod separated by account, state, credentials, network, storage and CI identity, each wall proved by a test; on DigitalOcean exactly two Postgres clusters; company and tool sites on non-prod; step 1 nets ≈ +7 USD/month (savings first, then the Verikora pilot base). Amends ADR-022 § 3/§ 5 | Proposed |
| [ADR-024](ADR-024-composer-integration.md) | Krizaka Composer in the products: a thin-seam fork of Puck merged from upstream releases (divergence measured, security picks within 7 days), the React-free contract `@krizaka/composer-document` under `@krizaka/ui`, blocks declared once by `defineSection` with a versioned catalogue, the stored document as the one truth (internal codec), server validation per tenant, admin settings and audit, a one-way per-shop switch from the hand-made composer; Folioviv only, krizaka.com refused | Proposed |
| [ADR-025](ADR-025-demo-data-v2-one-cast-additive-seeds.md) | Demo data v2: cast v2 in `@krizaka/org` (people who sign in, customer-value titles), one `seed --cast` per app run as ordered domain modules (pure plan, one transaction), UUIDv5 ids and an injected clock, additive only (v1 rows marked retired, never deleted), 12 Folioviv demo shops one per look preset, media by logical key under `apps/<app>/demo/`, content fingerprint, local = CI = dev through `seed-dev.sh`, never production | Proposed |
| [ADR-026](ADR-026-automation-strategy.md) | Automation strategy: one home per kind (shared bins in `@krizaka/config`, reusable workflows and actions here, a repository's own `scripts/`, the machine's crons, LaunchAgents and agent hooks only in krizaka-agents `install.json`), one catalogue generated daily by the matrix and shown in the cockpit, one git hook chain from `@krizaka/config` (`krizaka-hooks install` in `prepare`), regexes over 80 characters replaced by data, parsers or named parts, every check tested by fixtures, a committed docs map with its PR check, guards in the conformance matrix; a seven-phase plan of 61 issues | Accepted |
| [ADR-027](ADR-027-architecture-as-code.md) | Architecture as code: the current state generated from `main` by `@krizaka/architecture` (extended: versions, org dependencies, every ecosystem); each system's C1 and C2, current and target, written in LikeC4 in its home repository's `docs/architecture/` against one org specification (`#planned`, `#retiring`); the systems, the standard views and the facts (units, versions, latest tags, library → asset dependencies) generated from `main` by one tool here (`tools/architecture/`), never typed; drift (`undocumented`, `phantom`, `reached`, `gone`, `missing`, `invalid`) counted by the matrix rule `architecture-model`, reported first; rebuilt on the Mac after each workspace sync; one interactive view in the cockpit (React Flow, ELK), later `@krizaka/ui/diagram` | Accepted |
| [ADR-028](ADR-028-security-observability-lane-and-dashboards-as-code.md) | The Security, Observability & SRE lane (id `security`): started on demand, on an alert (> 24 h, 1 a day) or at a weekly check-in, never continuously; one Grafana per environment, the dev and prod links only in `policy.json` (an operator console pinned by the schema), shown with live headline numbers in the cockpit; reading surfaces in the founder's register as Grafana JSON in each app's `infra/observability/` (Grafana Pages blocked as code: public preview, no content in the API), linted by `dashboard-linter`, checked by `krizaka-dashboards check` in the one hook chain and CI; SLOs as data with burn-rate alerts; k6 load tests on dev only; the service graph from OpenTelemetry next to ADR-027's C1/C2; the Grafana Cloud features inventory | Proposed (prod stack, tokens, alert channel and DPA are the founder's) |
