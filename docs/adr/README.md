# Organisation ADRs

Decisions that span several Krizaka repositories. A decision that belongs to one repository lives in that repository
(`krizaka-ui/docs/adr`, `orazaka/docs/adr`…).

| ADR | Decision | Status |
|---|---|---|
| [ADR-001](ADR-001-krizaka-accounts.md) | The sign-in standard of every Krizaka product (krizaka-users, `SignInProviders`, linking by verified e-mail, native PKCE) and Krizaka accounts for the krizaka.com properties (a thin `krizaka-accounts` host with comments) | Accepted (runtime waits on cost approval) |
| [ADR-002](ADR-002-dev-preview-status-is-data.md) | « Dev preview » is a checkable bar (docs/standards/dev-preview.md); a product's status is data (`dev-preview.json`), gated at krizaka.com's build | Accepted |
| [ADR-003](ADR-003-mobile-service-discovery.md) | Mobile apps discover their backend addresses from a signed manifest on krizaka.com (`@krizaka/discovery`, Ed25519, host allow-list), so a URL change never forces a store republish | Accepted |
| [ADR-004](ADR-004-expo-app-shell.md) | Expo apps share one package, `@krizaka/app-client` (session, discovery, API client, gates, auth, settings) and a wiring-only `template-expo-app` |  Accepted |
| [ADR-005](ADR-005-tauri-app-kit.md) | Tauri apps share one Rust crate, `krizaka-tauri-kit` (folder scope, files, menu bar, deep links, update), its TypeScript bindings and a wiring-only `template-tauri-app` | Accepted |
| [ADR-006](ADR-006-krizaka-ts-organize.md) | Krizaka TS (`krizaka/krizaka-ts`, backend packages under `@krizaka/`) and `@krizaka/organize`: name, avatar, description, tags, collections and an undeletable default collection for every entity, a table-per-kind generator with the invariants in the database | Accepted |
| [ADR-008](ADR-008-native-video-bunny-stream.md) | Native video behind `@krizaka/ui/native`: playback stays on `expo-video` with server-signed Bunny addresses or tokens, uploads signed by the server (no key in the app), Bunny's React Native SDK adopted only after a trial on our Expo SDK and the New Architecture | Proposed (design; trial waits, Orochia paused) |
| [ADR-009](ADR-009-prices-are-data.md) | Prices are data: one price catalogue per product in `@krizaka/settings`, edited by the admin, versioned with effective dates, audited; public pages read only the catalogue | Accepted (shipped; Orazaka Java side planned) |
| [ADR-010](ADR-010-krizaka-storage.md) | `krizaka-storage` (`@krizaka/storage` and the Spring block): the admin chooses where files live (S3-compatible or HTTP), the user may choose when allowed, residency claims are generated from the configuration | Accepted (design) |
| [ADR-011](ADR-011-default-media-in-the-org-json.md) | Default media are central: Bunny `defaults/v1/<kind>/`, listed in the `defaults` section of the Krizaka org JSON (`@krizaka/org`), read with `listDefaults` / `defaultFor`, never hard-coded or bundled | Accepted |
| [ADR-012](ADR-012-licensing-libraries-open-products-fair-source.md) | Libraries stay Apache-2.0 (DCO); products (Yomizaka, Akinaza, the Orazaka engine) move to FSL-1.1-ALv2 from the licence commit, Apache-2.0 after two years (CLA); content assets go private by Oussama's decision; trademarks never licensed; a licence gate on the SBOM | Accepted (libraries) · Proposed (products, `needs-oussama` PRs) |
| [ADR-013](ADR-013-guards-and-local-sonar.md) | Sonar rules run locally (sonarjs in `@krizaka/config`; PMD + SpotBugs in `krizaka-parent`; ArchUnit for the architectural lessons); shift-left to the IDE and hooks; one source per rule set; less in-house (ESLint suppressions, Renovate, add-to-project) | Accepted |
| [ADR-014](ADR-014-bunny-org-cdn-and-apps.md) | The Bunny media library, layout v2: `org/v<n>/` (Krizaka's own data and defaults: org JSON, apps config, defaults and avatar tones, brand, maps, films, discovery), then `sites/<site>/<kind>/` (www, blog, ui, java, each dev site), then `apps/<app>/` (runtime data only), and `pr-assets/`; at most five folders; a new write outside v2 fails; unused old objects are deleted | Accepted (migration in progress) |
| [ADR-015](ADR-015-ai-code-audit-measured-and-enforced.md) | The external « AI code » audit, measured (`tools/code-health`) then enforced as build rules: NullAway + JSpecify `@NullMarked` (Error Prone only as its host), closed sets as types, DTO + `@Valid` + `ProblemDetail`, PMD limits and ArchUnit rules in `krizaka-parent` / `krizaka-quality` / `krizaka-test-support`, the type-aware strict layer of `@krizaka/config`, an anti-slop template section and a single-file Claude hook; existing debt ratcheted, no flag day | Accepted |
| [ADR-016](ADR-016-identity-federation-trusted-devices-risk.md) | Identity: federation by standards (OIDC, SAML 2.0, SCIM 2.0; Okta is one IdP), krizaka-users kept over Keycloak/Zitadel/Ory, passkeys first, NIST 800-63B-4 passwords, trusted devices (device keys, refresh rotation, DPoP), an explainable risk engine under Loi 25, ports in the open core and enterprise adapters (SAML/SCIM) in a private repository, identity secrets sealed under `AUTH_VAULT_KEY` | Accepted (design; paid items need Oussama) |
| [ADR-017](ADR-017-e2e-journeys-test-shape.md) | Tests prove the product: journeys first, a product never tests the library; catalogue format, budgets, flake policy |
| [ADR-018](ADR-018-workflows-by-concern-profiles-budgets.md) | Workflows by concern (`<area>-<what>.yml`, literal job names, renames never rename a check), repository profiles with default sets (`docs/standards/ci-profiles.json`), speed budgets PR < 10 min / queue < 15 min measured weekly (`org-ci-speed.yml`), buildpacks where they fit, a daily repository health scorecard composed from the existing checks | Accepted (slice 1 shipped) |
| [ADR-019](ADR-019-java-building-blocks-on-github-packages.md) | The Java building blocks are published on GitHub Packages (no Maven Central Publisher Pro): release with `GITHUB_TOKEN`, consumers read through `krizaka-parent`, versions 0.1.0/0.2.0 stay on Central | Accepted (roll-out krizaka-internal#1879) |
